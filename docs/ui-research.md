## 本轮设计结论

### 1. 首屏先回答“现在能不能用”

首页顺序调整为：

1. 设备身份、数据来源和最后更新时间
2. Cellular 与 Internet 分开显示
3. 当前制式、CA 聚合、PLMN、Ping 和丢包
4. 三个核心无线指标
5. 最近 60 秒曲线
6. PCC/SCell、邻区、完整字段和事件时间线

这条顺序更贴合高铁、隧道和弱信号场景：用户先看连接是否仍然可用，再判断是无线变化还是用户路径断流。

### 2. 手机端使用“平面分层”，不使用装饰性大图

采用深色平面、细边框、单一青绿色主强调色，使用红色/黄色表达异常语义。卡片保持中等圆角和较低阴影，避免把大量数据变成一堆相同的浮动胶囊。

图表使用轻量 SVG，不引入重量级图表框架。指标值使用等宽数字特性，长 Cell ID 和原始字段通过换行处理。

### 3. 证据状态必须一直可见

Fixture、缓存快照和未验证来源继续显示明确提示；null 仍显示为长横线，扩展字段只在有值时出现。视觉精美化不能改变“没有真实返回就不算 supported”的规则。

### 4. 登录与 Dashboard 是两种使用阶段

登录界面只处理 H168 管理密码和本地会话恢复；认证成功后直接进入 Dashboard，并由
集中轮询自动抓取实时数据。endpoint、HTTP/Huawei 结果、延迟、解析字段和脱敏 RAW XML
仍由 Bridge/内部诊断代码保留，但不作为生产界面入口。

Dashboard 是移动监控台：减少首屏噪音，把细节下沉到分区。登录和 Dashboard 共享同一套
颜色、边框、焦点和安全提示，但不强行共用相同的信息密度。

## 实现边界

- 本轮只修改 React 结构和本地 CSS，不引入重型 UI 框架。
- 没有复制第三方仓库代码、GPL 前端、图标或图片。
- 视觉示例数据仍然只能来自现有 fixture；没有真实 H168-383 时，不在文档或页面声称实机验证成功。
- 这轮完成的是视觉和信息架构，不等于完成 iPhone 真机、Safari、Surge MITM 的最终验收。
